## **Revenge of the PETSCII Robots**

### Commentary

I was not intending to work on _Revenge of the PETSCII Robots_ in January since I had a lot of work to do at my actual job(s). I ended up doing much more than nothing. I'm learning disclipine and to not only code when I feel like it. I want this game done. Hopefully by the end of 2026. I want to work on projects that are fully mine.

### Additions

* Added a unified movement function that combines move and move-push capabilities
- Previously, every object type moved with different code.
- Pushing or not pushing an object had different code as well.
- Currently, everything can move using the same move function.
* Added get facing function
- Facing is the direction that the instance is currently turned to
- Affects what the instance can interact with and what direction they shoot
* Added a create effect function for creating sparks etc.
* Added reverse direction function.
- Returns the opposite direction of the input.
* Added facing to image angle function.
- Used for rotating an effect instance.

### Fixes

* Greatly improved enemy random walk code.
* Improved projectile collision code.
- Prevents player bullets from hitting the player as they are spawned.
- Improved collisions with all other instances. 
* Shrunk projectile hitboxes to prevent them from hitting objects they did not visually hit.
- Projectiles fly above the ground, unlike most other instances. 
- The game's perspective could cause future problems with this.
* Fixed effect when player bullet strikes instance.

### Cleanup

* Rewrote various functions to make them portable.
- This involves changing function inputs and outputs to take in more data and rely less on changing code inside the instance that runs them.
- I plan on using GameMaker less in the future.
* Removed un-used functions and variables.
* Separated functions into groups within separate script files for better organization.
* Reorganized player movement input code to be less redundant.
* Functionized enemy and player code.
* Reorganized enemy parent object creation code.

### Short-Term Goals

* Combat testing to fully test all interactions improved / fixed so far.
- Will likely involve enemy chase behavior improvements.
- Add Moverbot breaking breakable walls.
* Finish goo-bomb.
* Re-add Laserbot.
- Figure out how laser will work for gameplay.

### Notable Bugs

* Pushing objects can sometimes get the pushing instance stuck in another instance.
- Likely due to the universal movement function checking for collisions and not checking for multiple collisions after it finds one. 
- Currently, the universal movement function counts the pushing instance as "not blocked" if the blocking instance is the pushable instance. If multiple collisions are not checked, this potentially causes problems. 
* Instances slightly stick out of walls when they approach from the top.
